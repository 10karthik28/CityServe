# CityServe - Programmer & Technical Documentation

## 1. System Overview
Kerala CityServe is a full-stack, web-based Municipal Service Request Management System. It allows citizens to report municipal issues, track their resolution, and provide feedback. The application follows a monolithic architecture built with a Python backend and a vanilla JavaScript frontend.

## 2. Technology Stack & Libraries
- **Backend Framework:** Flask (v3.0.3)
- **Database Engine:** MySQL (via XAMPP)
- **Database Connector:** PyMySQL (v1.1.1) utilizing `pymysql.cursors.DictCursor` to return dictionary rows.
- **Security:** `Werkzeug` (v3.0.3) for cryptographic functions (`generate_password_hash`, `check_password_hash`) and `secure_filename` for file sanitization.
- **Frontend Details:** HTML5, CSS3 natively handled. Dynamic DOM manipulation and API calls made through Vanilla JS (`Fetch API`).
- **Mapping APIs:** Leaflet.js & OpenStreetMap (Nominatim).

## 3. Map API Integration & Geospatial Details
The project utilizes an open-source mapping stack integrated directly on the client side (`request_service.html`), operating seamlessly with the Flask backend:
- **Map Rendering:** Leaflet.js (v1.9.4) renders the map UI, using standard tile layers generated by OpenStreetMap.
- **Boundaries:** The view is strictly bounded to the Ernakulam district via `L.latLngBounds` using max coordinates `[9.75, 76.05]` & `[10.30, 76.60]`.
- **Search (Forward Geocoding):** User searches execute asynchronous `fetch` wrappers connecting to the **Nominatim API** (`https://nominatim.openstreetmap.org/search`). The `viewbox` parameter enforces the search to remain within Ernakulam limits.
- **Pinpoint (Reverse Geocoding):** Leaflet `map.on('click')` events are intercepted to fire a reverse geocoding fetch request to Nominatim (`/reverse`), translating geo-coordinates (`lat`, `lng`) to human-readable locale strings.
- **Backend Sync:** Final selected Coordinates and Display Names are injected into hidden form inputs (`#lat`, `#lng`) and sent via `multipart/form-data` constraints to the Flask API.

## 4. Flask Backend Architecture & Flow
The backend runs in `app.py`, eschewing ORMs (like SQLAlchemy) for raw parameterized query execution to guarantee lightweight operations & full control.

### 4.1. Core APIs and Services
- **`GET /<filename>.html`:** Lightweight static file router.
- **Auth Module (`/api/auth/*`):** Handles citizen registration and hybrid login procedures parsing whether roles are `'user'` or `'authority'`. Secures HTTP sessions over server-side cookies (`SESSION_COOKIE_HTTPONLY=True`).
- **Issues Module (`/api/issues/*`):**
  - Uses `request.files` mapped to `secure_filename` with UTC injected timestamping for atomic file saving.
  - File saving constraints are hard-capped (`MAX_CONTENT_LENGTH=5MB`).
- **Authority Module (`/api/authority/*`):** 
  - Dynamically routes issues by evaluating matching categories against authority department definitions mapping (`DEPT_CATEGORY`).
  - Capable of injecting localized personnel tables.
- **Report & Analytics Service (`/api/authority/report`):** Features complex joint metrics parsing feedback matrices alongside resolution statuses filtered over explicit date aggregations (`MONTH(created_at)` vs All-Time).

## 5. Database Schema (MySQL)
Located thoroughly in `schema.sql`:
1. **`users`:** Holds citizen credentials dynamically.
2. **`authorities`:** Department admin entries (pre-seeded on Flask App instantiation).
3. **`personnel`:** Field personnel mapping, holding foreign constraints cascading back to `authorities`.
4. **`issues`:** Master transactional table containing geospatial data (`lat`, `lng`), dynamic issue-tags, uploaded `image_path` URIs, and user FK relationships.
5. **`feedback`:** Holds UNIQUE constraints on `(issue_id, user_id)` preventing duplicate ratings.
